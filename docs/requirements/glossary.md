# Glossary

One name per thing (QA-USE-03): use the term in the first column, never the ones in the last column.
UI rows name what the user sees; the domain rows, grouped by area, name what the app works on. A
word may be a term in two areas with two meanings; each row says which.

## Repo and worktrees

| Term           | Meaning                                                                                                                                                                                                                   | Not                             |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| main worktree  | The worktree that holds the repo's git dir; a repo is named by it and found through it when its remembered worktree is gone.                                                                                              | primary worktree, root worktree |
| working tree   | A worktree's files on disk, as opposed to its index and its HEAD commit.                                                                                                                                                  | working files, working copy     |
| session        | The core's in-memory state for an open worktree and its repo, shared by every window on it: the log, the write queues, outside-change watching, the message draft, the merge drafts. It ends when the last window leaves. | connection                      |
| outside change | A change another program (a terminal, the editor) made to the repo or the working tree; the app notices it and reloads.                                                                                                   | external change                 |
| detached HEAD  | A worktree whose HEAD is a commit, not a branch; commits made there belong to no branch. Every rebase runs detached.                                                                                                      | detached state                  |

## Log

| Term               | Meaning                                                                                                                                                                                                                      | Not                  |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| log                | The commits of every branch and tag with their graph, loaded once per repo and streamed as rows; the log view shows it and filters narrow it. A single ref's commits are its history.                                        | git graph            |
| history            | The commits reachable from one ref: a branch's or a tag's history, what the branch filter shows for it. The whole repo's commits are the log.                                                                                |                      |
| SHA                | A commit's full identity as git prints it, 40 or 64 hex digits; what every call names a commit by. The UI shows its short form, the short hash.                                                                              | commit id, object id |
| filter             | A narrowing of the log by author, by refs or by path; filters combine and each is cleared on its own. A search narrows nothing.                                                                                              |                      |
| search             | Finding commits in the shown log by message text or hash; it hides nothing and highlights the matches.                                                                                                                       | find                 |
| commit details     | A commit's full message, author, committer, dates, parents and changed files.                                                                                                                                                | commit info          |
| changed file       | A file a commit or a comparison touched, with its status: added, modified, deleted, renamed, copied, type changed.                                                                                                           | diff entry           |
| comparison         | Two compared commits, the from side (selected first) and the to side (selected second), and the files that differ; or a commit compared with the working tree. Swap reverses it. The sides are never called older and newer. | compare mode         |
| from side, to side | The comparison's two commits: from is selected first, to second; a diff reads from "from" to "to".                                                                                                                           | a/b, base/target     |

## Diffs (shared by Log and Changes)

| Term           | Meaning                                                                                                                                  | Not           |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| line selection | The changed lines of one diff the user chose to stage, unstage or discard, named by their line numbers on the side they were shown on.   | partial stage |
| fingerprint    | Identifies the content a diff or a conflicted file was shown from; a write sends it back and is refused when the file changed meanwhile. | etag, stamp   |

## Changes

| Term          | Meaning                                                                                                                                                                                                                                                      | Not                           |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------- |
| change        | One file's uncommitted difference in the worktree, in one of four states: staged, unstaged, untracked, conflicted. A file can have a staged and an unstaged change at once. In a conflicted file, "change" means a difference between the sides (Conflicts). | modification, pending change  |
| conflicted    | Left by a stopped operation with unmerged sides in the index.                                                                                                                                                                                                | unmerged                      |
| discard       | Drop a working-tree change (a file, a hunk or a line selection) back to the index's version, or delete an untracked file. Confirmed first. Not a revert (a commit) nor a reset (a branch).                                                                   |                               |
| message draft | The commit message as typed and not yet committed, kept in the worktree session until the commit succeeds.                                                                                                                                                   | commit draft, unsaved message |

## Branches

| Term           | Meaning                                                                                                                                                                                                          | Not                                     |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| ref            | A branch, a remote branch or a tag: what the branch picker lists and a filter takes. Given to git by its full name wherever a short name could mean two refs.                                                    | reference                               |
| current branch | The branch the worktree's HEAD is on.                                                                                                                                                                            | active branch, checked-out branch       |
| remote branch  | A remote's branch as last fetched, shown under its remote (`origin/main`).                                                                                                                                       | remote-tracking branch, tracking branch |
| upstream       | The remote branch a branch tracks: a pull integrates it, a push goes to it, ahead and behind count against it. Set by checking a remote branch out or by the first push.                                         | tracking branch                         |
| start point    | The commit a new branch or worktree starts at: a commit, a branch or a tag. A branch started from a remote branch gets no upstream.                                                                              | source branch                           |
| check out      | Make a branch the worktree's current branch, or detach HEAD at a commit or a tag. A remote branch checks out as a new branch with it as upstream. The window switches worktree or view; a branch is checked out. | switch branch                           |
| branch in use  | A branch another worktree has checked out, or is rebasing or bisecting; check out, delete and update branch refuse it and name that worktree.                                                                    | locked branch, busy branch              |

## Sync

| Term          | Meaning                                                                                                                                                                                                                          | Not                                             |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| sync          | Exchanging commits with remotes: fetch, pull, push, force push and update branch; the sync controls and the jobs menu. Integrating locally is not sync.                                                                          | synchronise                                     |
| job           | A sync action running in the background with progress and cancel: fetch, pull, push, force push, update branch. Jobs belong to the repo session and show in the jobs menu. An operation is git's state in a worktree, not a job. | task, process, background action, remote action |
| update branch | Fast-forward a branch that is checked out nowhere to its upstream, as a job, touching no worktree's files. A diverged branch is reported, not changed.                                                                           | fast-forward branch, sync branch                |

## Operations

| Term          | Meaning                                                                                                                                                                                              | Not                                                   |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| operation     | A merge, rebase, cherry-pick or revert (its kind) git left in progress in a worktree after a stop; it waits for continue, skip or abort. A squash or fixup in progress is a rebase.                  | running operation, pending operation, sequencer state |
| stop          | An operation ending a step without finishing: on conflicts (its files are conflicted), or for another reason git names (a hook, signing, a file in the way).                                         | pause, interruption                                   |
| integrate     | Bring a ref's commits into the current branch by merge or by rebase; a pull integrates the upstream. With stash, local changes are stashed first and restored after a clean integrate.               |                                                       |
| cherry-pick   | Replay the selected commits' changes onto the current branch, oldest first; with options to record the origin and to apply without committing. Never "pick" in UI text, which is what a picker does. |                                                       |
| revert        | Replay the inverse of the selected commits onto the current branch, newest first; with the option to apply without committing.                                                                       | undo commit                                           |
| waiting stash | The stash entry a pull, merge or rebase with stash made and could not restore cleanly; it waits until no file is conflicted and the user restores or drops it.                                       | autostash, pending stash                              |

## Conflicts

| Term                          | Meaning                                                                                                                                                                                                                      | Not                                                |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| conflicted file               | A file a stopped operation left with unmerged sides. Its kind decides the way out: text in the merge editor; a deletion on one side, a binary or a symlink by choosing a side; a rename or a submodule by hand.              | conflict file, unmerged file                       |
| side                          | One version of a conflicted file: the current side (checked out), the incoming side (brought in) or the base (what both started from). Which ref or commit a side is depends on the operation.                               | ours, theirs, mine                                 |
| base                          | The version both sides started from; the result starts as the base with every change open.                                                                                                                                   | common ancestor                                    |
| change (of a conflicted file) | A run of lines where the two sides differ: a conflict, where both sides changed the lines differently, or a one-side change, which only one side made. A change both sides made alike is none. The user handles each change. | region, conflict region                            |
| conflict                      | A change both sides made differently, which git could not choose; in the file it is a block between conflict markers.                                                                                                        | conflicted change                                  |
| result                        | The merged text being built in the merge editor; it starts as the base and is saved to the working file.                                                                                                                     | merged file                                        |
| merge draft                   | The result with its unsaved edits and each change's state, kept in the worktree session until the file is resolved, the operation is aborted or the app quits.                                                               | unsaved result, unsaved merge result, merge result |
| conflict marker               | One of git's lines fencing a conflict in the file; none may be left when the file is marked resolved.                                                                                                                        | diff marker                                        |
