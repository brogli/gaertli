# Feedback and settings

| ID       | Prio   | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| -------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-UX-01 | MUST   | Every action ends with a visible result. Errors include git's original message.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| FR-UX-02 | MUST   | The app writes an app log, so problems can be traced. By default it holds the app's own errors, every git command that fails, with git's output, and every editor command that fails to start. With debug mode on (FR-UX-19) it also holds every git command the app runs, with its result, including those it runs on its own to stay current, and every editor command it starts; switching debug mode takes effect at once, also for a WSL repo's commands. The window itself lists no git commands; Settings name where the app log is.                                                                                                                                                                                                                                                                                                                                             |
| FR-UX-03 | MUST   | Confirmation before: hard reset, force push, discard changes, remove worktree, delete unmerged branch, squash or fixup, abort a running operation, drop a stash.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| FR-UX-04 | MUST   | Settings, opened from the toolbar, hold: external editor (FR-ED), protected branches, default pull mode, diff mode, whether diffs ignore whitespace, auto-fetch interval, theme (FR-UX-06), the base folder for new worktrees (FR-WT-02; one per environment, local and each WSL distro; by default the folder that holds the repo's main worktree) and debug mode (FR-UX-19). Saving changes only these settings: the recent repos and the windows to reopen stay as the app last recorded them, even when they changed while Settings were open.                                                                                                                                                                                                                                                                                                                                      |
| FR-UX-05 | MUST   | Keyboard shortcuts for the main actions, anywhere in a main window: Ctrl+K commits (FR-CHG-05), Ctrl+T pulls (FR-SYNC-02), Ctrl+Shift+K pushes (FR-SYNC-03), F5 refreshes (FR-REPO-04), Ctrl+Shift+N opens a new window (FR-WT-13) and Escape ends a comparison (FR-CMP-01, FR-CMP-04). A shortcut does exactly what its control does at that moment, and nothing when that control is disabled or not offered. While a dialog, popup or menu is open, keys belong to it and no shortcut acts; Escape in a text field belongs to the field (in the log search it empties the search, FR-LOG-05). Each shortcut shows on its control, in muted text: inside the Commit button at its right, and at the right of the "New window" and "Stop comparing" entries; in the tooltip of Pull, Push, Refresh and the comparison's close button, after the action's name ("Push · Ctrl+Shift+K"). |
| FR-UX-06 | MUST   | Themes: the system's choice of light or dark, Light, Dark, and the dark themes Gruvbox dark, Catppuccin Mocha, Nord and Dracula, each in its original colours. A theme covers every window and all of its content, the diff included, and a change shows at once. The app names each theme's authors and licence.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| FR-UX-07 | MUST   | A window shows the toolbar and three views: the log view, the commit detail view (the selected commit, or the comparison) and the changes view (the change list and the commit box).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| FR-UX-08 | MUST   | The window is usable at any width down to phone width, showing as many of the three views as fit. When all three fit, they show side by side, their widths adjustable. When two fit, the log view stays and a switch picks the commit detail view or the changes view; selecting a commit brings up the commit detail view. When one fits, a switch picks among all three; a click on a commit keeps the log view, opening the commit (a double-click or Enter) shows its commit detail view. The switch shows how many files the changes view lists. The switch is a row of tabs above the views: a click, or an arrow key once a tab has focus, picks a view. Widths the user sets are remembered separately for three views side by side and for two, also after a restart. Switching views keeps each view as the user left it: its scroll position and the typed commit message.   |
| FR-UX-09 | SHOULD | At every width (FR-UX-08) controls fit their view: a file's actions stay on its row, a toolbar stays on one row, a checkbox stays beside its label. Text too long for its space ends in an ellipsis and shows in full on hover. A list column with no room left for a readable value is hidden instead of shrunk to a sliver, the least useful column first; the remaining columns still line up. A control without visible text has a tooltip naming its action.                                                                                                                                                                                                                                                                                                                                                                                                                       |
| FR-UX-10 | SHOULD | Views show data formatted, not raw: the commit detail view shows the subject in the text font, not the fixed-width one; author and committer as labelled fields with dates (the committer only when it differs from the author); parents as short hashes. Dates show relative to now in the UI's language ("3 days ago", "just now" under a minute); hovering one shows its exact date and time, in the date format of the user's system.                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| FR-UX-11 | MUST   | Every text the UI shows is translatable, plurals included, also the built-in texts of its controls (a close button's label, a list's "no results"). The only language is English. Git's own messages are shown as git wrote them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| FR-UX-12 | MUST   | The user sees and can abort running jobs (fetch, pull, push, branch updates) in the toolbar's jobs menu: it shows that jobs are running, and its list shows each job with its progress and a way to abort it. Starting or ending a job never moves the layout.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| FR-UX-13 | MUST   | Every file list (commit detail view, changes view, diff window) shows a file's status as an icon, not a letter: added, modified, deleted, renamed, copied, type changed, untracked, conflicted. The icon's tooltip names the status.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| FR-UX-14 | MUST   | A dropdown, popup or menu closes on the first click outside it and on Escape.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| FR-UX-15 | MUST   | An error notice, and any notice with a button (e.g. Try again, Copy hash), stays until the user closes it or a newer result of the same action takes its place (fetch, pull and push count as one action here). Other notices close by themselves after 5 seconds, but not while the pointer is over them. A notice never removes the notice of another action, and a closed notice does not come back. A notice is opaque: the content behind it does not show through.                                                                                                                                                                                                                                                                                                                                                                                                                |
| FR-UX-16 | MUST   | When a git action fails because another program holds one of git's lock files on the repo, the app says that another program is using the repo and offers to run the action again.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| FR-UX-17 | MUST   | Dialogs are not cramped: one field per row, each with its label, and the buttons together.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| FR-UX-18 | MUST   | The app uses the same fonts on Windows and Linux: one for its text and one for fixed-width text (hashes, diffs).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| FR-UX-19 | MUST   | Debug mode (Settings) is for trying the app out: each main window then offers actions that show a sample notice of an error, a warning and a success. Debug mode also makes the app log detailed (FR-UX-02). Started with the environment variable `NEBEGIT_LOG=debug`, the app log is detailed from its first line, before the settings are read, and stays so for the whole run whatever debug mode says.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| FR-UX-20 | SHOULD | The user resizes the parts of a window by dragging the divider between them without selecting any text: a drag selects nothing, wherever the pointer passes, and a selection made before the drag stays. This holds for every divider: between the main window's views, in the commit detail view, and in the diff window between the file list and the diff and between the diff's two sides.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
