# Changes, commit and conflicts

## Changes and commit (CHG)

| ID        | Prio   | Requirement                                                                                                                                                                                                                                                                                                                                                                                             |
| --------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-CHG-01 | MUST   | Show changed files of this window's worktree in groups: staged, unstaged, untracked, conflicted.                                                                                                                                                                                                                                                                                                        |
| FR-CHG-02 | MUST   | Stage and unstage whole files, and all files at once.                                                                                                                                                                                                                                                                                                                                                   |
| FR-CHG-03 | MUST   | Stage and unstage single hunks and selected lines in the diff (whitespace shown, FR-DIFF-06). A hunk is git's hunk as the diff shows it; a file's mode change belongs to no hunk. An action refuses, changing nothing, when the file changed since the diff was shown.                                                                                                                                  |
| FR-CHG-14 | MUST   | Where a hunk replaces lines one for one, a selected line is staged or unstaged as a whole change, its removed and its added version together. Where it replaces them with a different number of lines, a line selection takes the whole hunk.                                                                                                                                                           |
| FR-CHG-04 | MUST   | Show the diff of any changed file, in the diff window (FR-DIFF-07).                                                                                                                                                                                                                                                                                                                                     |
| FR-CHG-05 | MUST   | Commit staged changes with a message. Blocked when nothing is staged or the message is empty or only spaces. The Commit button names how many files are staged: "Commit (3)".                                                                                                                                                                                                                           |
| FR-CHG-06 | MUST   | Amend the last commit: ticking "Amend last commit" fills the message field with that commit's message, unless the field already holds text; the Commit button then reads "Amend" and needs nothing staged. Not offered before the first commit or while an operation (merge, rebase, …) is in progress. Warn if that commit is already pushed.                                                          |
| FR-CHG-07 | MUST   | Git hooks run as usual. If a hook fails, show its output.                                                                                                                                                                                                                                                                                                                                               |
| FR-CHG-08 | MUST   | Keep the message draft until the commit succeeds.                                                                                                                                                                                                                                                                                                                                                       |
| FR-CHG-09 | SHOULD | Commit and push in one action: with "Push after commit" ticked, a successful commit is pushed the way Push pushes it, upstream handling included (FR-SYNC-12). The option is unavailable while amending, on a detached HEAD and in a repo without a remote.                                                                                                                                             |
| FR-CHG-10 | MUST   | Discard changes per file, hunk or selected lines, with confirmation. Line selections and refusals work as for staging (FR-CHG-03, FR-CHG-14); a discarded line gets its previous version back, never just removed.                                                                                                                                                                                      |
| FR-CHG-11 | MUST   | Committing never needs scrolling: the commit box stays in view however long the change list is.                                                                                                                                                                                                                                                                                                         |
| FR-CHG-12 | MUST   | The commit message field shows at least six lines without scrolling. It spans the commit box's full width.                                                                                                                                                                                                                                                                                              |
| FR-CHG-13 | MUST   | The change list follows the flat or tree choice of FR-LOG-16; the toggle sits in the changes view's header beside Stage all and Unstage all. Each group (staged, unstaged, untracked, conflicted) keeps its heading and shows its own files the chosen way. A file keeps its stage, unstage or mark-resolved button before its name and Open in editor and Discard at its end; a folder has no buttons. |

## Conflicts (CONF)

A pull, merge, rebase, cherry-pick, revert, squash or fixup that stops on conflicts lists the
conflicted files and opens the first one. The user resolves them file by file: a text file change by
change in the merge editor, any other file by choosing a version. Once no file is conflicted, the
user continues the operation; aborting it is possible throughout.

### The stopped operation

| ID         | Prio | Requirement                                                                                                                                                                                                                                                                                                                               |
| ---------- | ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-CONF-01 | MUST | Detect when a pull, merge, rebase, cherry-pick, or revert stopped on conflicts. List the conflicted files.                                                                                                                                                                                                                                |
| FR-CONF-09 | MUST | When a pull, merge, rebase, cherry-pick, revert, squash or fixup the user started in the app stops on conflicts, the diff window opens by itself on the first conflicted file. A conflict caused by a terminal command does not open it. While conflicted files remain, the operation banner's "Resolve conflicts" button opens it again. |
| FR-CONF-04 | MUST | Continue or abort the operation in progress. Continue is offered once no file is conflicted.                                                                                                                                                                                                                                              |

### Conflicted files

| ID         | Prio   | Requirement                                                                                                                                                                                                                                                                                                                        |
| ---------- | ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-CONF-02 | MUST   | Resolve a conflicted text file in the merge editor in the diff window, or open it in the external editor. A file that is not UTF-8 text opens in the external editor only.                                                                                                                                                         |
| FR-CONF-07 | MUST   | A conflict with no text to merge (one side deleted the file, a binary file, a symlink) offers a choice instead of the editor: keep the current side's version, take the other side's, or delete the file. Deleting asks first (FR-UX-03). Rename and submodule conflicts offer open-in-editor and mark-resolved only, and say why. |
| FR-CONF-03 | MUST   | Mark a file as resolved from the conflict list, as it is on disk.                                                                                                                                                                                                                                                                  |
| FR-CONF-19 | MUST   | When the shown file is resolved, the diff window moves to the next conflicted one, and says so when none is left.                                                                                                                                                                                                                  |
| FR-CONF-08 | SHOULD | A resolved file can be reopened as conflicted while the operation is still stopped. A staged file resolved during the stopped operation is reopened from its row, after a confirmation. A resolved file with nothing left to stage (resolved to the current side's version) stays in the conflicted list for this.                 |

### Merge editor: panes and changes

| ID         | Prio | Requirement                                                                                                                                                                                                                                                                                                                                                            |
| ---------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-CONF-05 | MUST | The merge editor shows three panes side by side: the current side's version on the left, the result in the middle, the incoming side's version on the right. The panes stay aligned change by change, and scrolling one scrolls the others.                                                                                                                            |
| FR-CONF-12 | MUST | Each side pane names its side and that side's role in the operation, as in the table below.                                                                                                                                                                                                                                                                            |
| FR-CONF-13 | MUST | Every difference between the sides is a change the user handles: a change only one side made, or a conflict, where both sides changed the same lines. The result starts as the base version with every change open; nothing from either side is in it until the user takes it. A change both sides made alike is in the result as git merged it and counts as handled. |
| FR-CONF-14 | MUST | An open change is tinted by kind in the side panes and the result: red for a conflict, blue for lines one side changed, green for lines one side added. A change only one side made is tinted on that side only. Handled changes are tinted neutrally.                                                                                                                 |

| Operation   | Current side (left)     | Incoming side (right)                |
| ----------- | ----------------------- | ------------------------------------ |
| merge       | the current branch      | the merged branch                    |
| rebase      | the branch rebased onto | the commit being replayed            |
| cherry-pick | the current branch      | the cherry-picked commit             |
| revert      | the current branch      | the state before the reverted commit |

### Merge editor: resolving

| ID         | Prio   | Requirement                                                                                                                                                                                                                                                                                                                                           |
| ---------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-CONF-10 | MUST   | Per change the user takes the left side, the right side, or both in either order ("Take left", "Take right", "Both, left first", "Both, right first"). Taking the side that left a change alone keeps the base. Or the user edits the result by hand and presses "Mark done", which handles the change as it then stands; a hand edit alone does not. |
| FR-CONF-15 | MUST   | "Apply non-conflicting changes" takes every open change only one side made.                                                                                                                                                                                                                                                                           |
| FR-CONF-16 | MUST   | Each take, "Apply non-conflicting changes" and "Mark done" is one undoable step; undo restores the change's state.                                                                                                                                                                                                                                    |
| FR-CONF-17 | MUST   | The toolbar acts on the selected change: the one last clicked in any pane or holding the result's cursor. The selected change is outlined and marked in all three panes, and a handled change is marked as handled in all three.                                                                                                                      |
| FR-CONF-18 | MUST   | Next and previous move between the open changes, also with Alt+Down and Alt+Up, shown on their buttons (FR-UX-05). The editor shows the selected change's position among the changes and how many are still open.                                                                                                                                     |
| FR-CONF-20 | SHOULD | Each pane of the merge editor shows line numbers for its own version of the file, and right-clicking one offers "Copy path:line", as in the diff view (FR-DIFF-23, FR-DIFF-24).                                                                                                                                                                       |
| FR-CONF-21 | SHOULD | Each pane of the merge editor has the diff view's search (FR-DIFF-17, FR-DIFF-20). Ctrl+F opens the search of the pane the cursor is in, otherwise the result's. A toolbar button opens the result's search and shows the shortcut (FR-UX-05).                                                                                                        |
| FR-CONF-06 | MUST   | "Save and mark resolved" saves the result and marks the file resolved in one action; Ctrl+S does the same from any pane, and the button shows the shortcut (FR-UX-05). It is offered once every change is handled and no conflict marker line is left in the result. The file is written with its working-tree line endings.                          |
| FR-CONF-11 | MUST   | The merge editor keeps the user's choices and edits per file, also across closing and reopening the diff window, until the file is resolved, the operation is aborted or the app quits; closing the diff window does not ask. A result whose file changed on disk meanwhile is kept, with a way to reload that discards it.                           |
