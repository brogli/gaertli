# Distribution and open source

| ID      | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| DIST-01 | Downloads from the project's release page: for Windows an installer and a portable archive; for Linux a package for the common package managers and an archive. The app needs git 2.42 or newer and the system's web view; it checks both at start, and a WSL distro's git on first use, and says clearly what is missing or too old.                                                                                                                                                                                                      |
| DIST-02 | Releases are started by hand from the main branch. An automated pipeline first runs the full checks on that commit, then builds every download with checksums and a verifiable record of where it was built, and offers them as an unpublished draft whose release notes list the changes since the last release. It refuses a version that is already released. A new draft replaces older unpublished ones. The maintainer checks the draft and publishes it unchanged: users download exactly what was checked. No hand-built binaries. |
| DIST-03 | No auto-update in v1: installing a newer version over the old one keeps the settings. Versions follow semantic versioning (`major.minor.patch`), raised by hand for each release, so package managers sort them right; every download of a release carries the same version. The app shows its version and the commit it was built from, e.g. `0.1.0 (abc1234)`; a build made outside the release pipeline shows `dev`.                                                                                                                    |
| DIST-04 | Windows users install from the release page without administrator rights; the installer makes the `nebegit` command available in Windows and WSL terminals opened afterwards. Uninstalling removes the app and that command and keeps the settings. If nebegit is running, the installer and the uninstaller ask the user to close it and try again; a silent run fails with a documented exit code instead of reporting success and leaving the old version in place.                                                                     |
| DIST-05 | The Windows archive runs from any folder without installing anything; the user docs say how to make its `nebegit` command available.                                                                                                                                                                                                                                                                                                                                                                                                       |
| DIST-06 | Windows users can also install, upgrade and uninstall nebegit with winget, with the same result as the installer (DIST-04).                                                                                                                                                                                                                                                                                                                                                                                                                |
| OSS-01  | Source is public on GitHub under **BSD-3-Clause**. All dependencies have compatible licences.                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| OSS-02  | A new contributor can build and run tests with the documented steps only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| OSS-03  | User docs: install, building the app from source in the project's development shell (on Windows an app that runs on its own; on Linux one that runs from that shell), first start, editor setup, known limits (WSL, SSH passphrase without agent).                                                                                                                                                                                                                                                                                         |
| OSS-04  | Nothing in the app assumes the owner's setup: no fixed paths, editor, remote host, or branch names.                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| OSS-05  | **Hard requirement: licence compliance.** No code, text or asset from another project enters the repo unless its licence is permissive (the dependency allow-list) and its notice ships with every release. Nothing is taken from copyleft (GPL, AGPL, LGPL) or source-available projects: other tools are inspiration only, taken from their documentation and behaviour, never their source, and described in our own words.                                                                                                             |
| OSS-06  | The README shows the project's state at a glance at its top: build status, latest release, licence and Go version.                                                                                                                                                                                                                                                                                                                                                                                                                         |
