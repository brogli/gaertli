# Distribution and open source

| ID      | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DIST-01 | Users download Gärtli from the project's release page: for Windows, an installer and a portable archive; for Linux, packages for the common package managers and an archive; for macOS, an archive (QA-PORT-04). The app needs git 2.42 or newer and the system's web view. It checks git at start (a WSL distro's git on first use) and says what is missing or too old; on Windows it also names a missing web view, on Linux the package installs the web view.                                |
| DIST-02 | Releases are started by hand from the main branch. On a commit that has passed the full checks, a pipeline builds every download with checksums and a verifiable build record, and offers them as an unpublished draft whose release notes list the changes since the last release. It refuses a version that is already released; a new draft replaces older unpublished ones. The maintainer publishes the draft unchanged, so users download exactly what was checked. No hand-built binaries. |
| DIST-03 | No auto-update in v1. Installing a newer version over the old one keeps the settings. Versions follow semantic versioning (`major.minor.patch`), raised by hand for each release so package managers sort them right; every download of a release carries the same version, in the app and in its file name. The app shows its version and the commit it was built from, e.g. `0.1.0 (abc1234)`; a build made outside the pipeline shows `dev`.                                                   |
| DIST-04 | Windows users install from the release page without administrator rights; the installer makes the `gaertli` command available in Windows and WSL terminals opened afterwards. Uninstalling removes the app and that command and keeps the settings. While Gärtli is running, the installer and the uninstaller ask the user to close it and try again; a silent run then fails with a documented exit code instead of reporting success.                                                          |
| DIST-05 | The Windows archive runs from any folder without installing anything; the user docs say how to make its `gaertli` command available.                                                                                                                                                                                                                                                                                                                                                              |
| DIST-06 | On Ubuntu, whose AppArmor denies user namespaces to programs without a profile, the Debian package installs the profile Gärtli needs, so the app starts with its web view's sandbox on; the sandbox is never turned off instead. A contributor whose development shell cannot start that sandbox is told at shell entry what to install.                                                                                                                                                          |
| OSS-01  | Source is public on GitHub under BSD-3-Clause. All dependencies have compatible licences.                                                                                                                                                                                                                                                                                                                                                                                                         |
| OSS-02  | A new contributor can build and run tests with the documented steps only.                                                                                                                                                                                                                                                                                                                                                                                                                         |
| OSS-03  | User docs cover: install, building from source in the project's development shell, first start, editor setup, known limits (WSL, SSH passphrase without agent).                                                                                                                                                                                                                                                                                                                                   |
| OSS-04  | Nothing in the app assumes the developer's setup: no fixed paths, editor, remote host, or branch names.                                                                                                                                                                                                                                                                                                                                                                                           |
| OSS-05  | No code, text or asset from another project enters the repo unless its licence is permissive (on the dependency allow-list) and its notice ships with every release; such code also names its source in a comment. Nothing is taken from copyleft (GPL, AGPL, LGPL) or source-available projects: other tools are inspiration only.                                                                                                                                                               |
