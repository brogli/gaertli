# Testing

Every acceptance case in a feature's task plan is covered by a test written before the code (TR-29);
cases that share a setup may share a test, as `it.each` rows or table cases. The test name carries
the requirement ID (TR-30).

| Level                    | What                                                                                                                                                                                                                                                            | Tools                                 |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| Parser unit tests        | Recorded git output → structs: odd file names, renames, empty repo, detached HEAD.                                                                                                                                                                              | Go test, inline fixtures              |
| Graph unit tests         | Hand-made histories → expected lanes.                                                                                                                                                                                                                           | Go test                               |
| Integration tests        | Real git against temp repos built by a helper, with a local bare repo as the remote. Every core method. They share one isolated git config per test process and run in parallel, since each git start is expensive on Windows.                                  | Go test                               |
| Protocol tests           | The RPC client and dispatcher over a pipe: errors and events crossing it, panic recovery. The WSL client against a real `nebegit-core` child process: version handshake, deploy consent, reconnect, path translation. This tests the WSL transport without WSL. | Go test                               |
| Frontend component tests | Stores and components with mocked bindings. The default for UI cases (TR-31).                                                                                                                                                                                   | Vitest, Vue Test Utils                |
| Frontend e2e             | Cases a component test cannot prove (TR-31), against a production build of the app with a mocked Go layer.                                                                                                                                                      | Playwright                            |
| Real-backend e2e         | Flows that mocks cannot prove (TR-31). The app runs in Wails server mode with the real core; each test gets its own scratch repos, settings file and stand-in editor. Linux only.                                                                               | Playwright                            |
| Performance checks       | A generated 100k-commit repo and a ~700 KB file; asserts QA-PERF-02/04/05/06/07. On demand.                                                                                                                                                                     | Go test (`bench` tag), `tools/mkrepo` |
| Manual checklist         | What needs real windows, a real WSL distro or a human judgement (below).                                                                                                                                                                                        | owner, per platform                   |
| Traceability check       | Every MUST FR ID has a test name or a manual entry.                                                                                                                                                                                                             | `tools/trace`, in CI                  |

## CI

CI follows TR-14, TR-26 and TR-42. Every pull request runs the Linux jobs side by side: lint
(treefmt, type check, traceability, licence check), the Go tests, the frontend tests with the Linux
build and the Windows cross-build (TR-26), the mock and the real-backend e2e suites, and the Go
tests with the race detector against the oldest supported git, built from source (QA-COMP-03). The
Windows job (the Go tests on Windows, where every git process is slow) and the macOS build are
billed at a multiple, so they run for pull requests into `main`, in the release workflow and when
started by hand. Pushes to `dev` and `main` start no run, since `task ci` checks each commit before
it is made. A newer push to a pull request cancels its run in progress. The performance checks run
on demand (`task bench`).
