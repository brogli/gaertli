# Build, packaging, repository layout

## Build

- Builds use Wails v3's Taskfiles, run through `go tool task` (TR-25).
- The Windows build embeds the `linux/amd64` core for WSL (ADR-3), so the app stays one download. `task build` cross-compiles the core first, then the GUI.
- Version and commit are stamped into the binary at release build time; Settings shows the version (QA-INST-03).
- `task build:server` builds the server-mode app the real-backend e2e suite runs (ADR-2).

## Packaging and releases

- Windows: a single `.exe`, zipped.
- Linux: a `.deb` and an `.rpm` (nfpm, via `wails3 tool package`), installing to `/usr/bin` and declaring GTK4, WebKitGTK and git as package dependencies; a `.tar.gz` (binary, `LICENSE`, `THIRD-PARTY-NOTICES.txt`) for other distributions.
- macOS: an unsigned `.app`, zipped, labelled untested (QA-PORT-04).
- Run-time prerequisites are git and the platform's web view (QA-INST-01, TR-04 to TR-06); the tar.gz bundles neither.
- No installer, no auto-update, no code signing (QA-INST-03). Unsigned Windows binaries trigger SmartScreen.
- Releases: GitHub Actions builds from a version tag and publishes the artifacts, `THIRD-PARTY-NOTICES.txt` and `SHA256SUMS` as a GitHub Release (QA-INST-02).
- A licence check runs in CI (QA-OSS-01, TR-19; `dependencies.md`).

## Repository layout

```
docs/
  requirements.md, requirements/    what the app must do
  architecture.md, architecture/    how it is built (this folder)
cmd/
  nebegit/                          GUI with an in-process core
  nebegit-core/                     headless core for WSL
internal/                           Go packages (components.md)
frontend/                           Vue app; also a Go package that embeds the built frontend
  bindings/                         generated by wails3, gitignored
  src/
    views/                          the top-level views of the main window and the diff window
    components/                     views, pickers, dialogs, the diff view, the log list
    stores/                         Pinia stores, one per area
    composables/  menus/  lib/  locales/  testing/
  e2e/                              Playwright, mocked Go layer
  e2e-real/                         Playwright against the app in server mode (TR-31)
build/                              Wails Taskfiles and packaging assets per platform
tools/
  gencore/                          go generate: RPC client, dispatcher, facade (TR-28)
  trace/                            requirement traceability check (TR-30)
  repocheck/                        tests for repository conventions
  licensecheck/                     licence check and THIRD-PARTY-NOTICES.txt
  mkrepo/                           generates test and benchmark repos
  bench/                            performance benchmark against the generated repo
.github/workflows/                  CI, release, nightly benchmark and e2e
Taskfile.yml                        setup, test, lint, build, dev, ci
flake.nix, flake.lock, .envrc       Nix dev shell (TR-24)
LICENSE  README.md  CONTRIBUTING.md  CHANGELOG.md  CLAUDE.md
```

`.bench/` holds the generated 100k-commit benchmark repo, gitignored.
