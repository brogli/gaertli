# Build, packaging, repository layout

## Build

- Builds use Wails v3's Taskfiles, run through `go tool task` (TR-25).
- The Windows build embeds the `linux/amd64` core for WSL (ADR-3). `task build` cross-compiles the core first, then the GUI. A bare `go build` on Windows needs `task build:core:embed` first, because `go:embed` cannot reach outside its package directory.
- Version and commit are stamped into the binary at release build time; the settings panel shows the version (QA-INST-03).

## Packaging and releases

- Windows: a single `.exe`, zipped, with the Linux core embedded.
- Linux: an AppImage. It does not bundle WebKitGTK; GTK4 and WebKitGTK 6.0 are system prerequisites (QA-INST-01).
- macOS: an unsigned `.app`, zipped, labelled untested (QA-PORT-04).
- Run-time prerequisites: git everywhere, WebView2 on Windows.
- No installer, no auto-update, no code signing (QA-INST-03). Unsigned Windows binaries trigger SmartScreen; the README says so.
- Releases: GitHub Actions builds from a version tag and publishes the artifacts, `THIRD-PARTY-NOTICES.txt` and `SHA256SUMS` as a GitHub Release (QA-INST-02).
- A licence check runs in CI: every Go package linked into the binaries and every JS production dependency must carry an allowed licence (QA-OSS-01, TR-19; `dependencies.md`).
- Nothing owner-specific in code or defaults, except that the default editor is the editor (QA-OSS-04).

## Repository layout

```
docs/
  requirements.md, requirements/    what the app must do
  architecture.md, architecture/    how it is built (this folder)
cmd/
  nebegit/                          GUI: the shell with an in-process core
  nebegit-core/                     headless core for WSL: --stdio server; launcher when given a path
internal/                           Go packages (components.md)
frontend/
  embed.go                          go:embed of the built frontend, handed to internal/app
  bindings/                         generated by wails3, gitignored
  src/
    views/                          MainView, WorktreeContent, CompareDiffView
    components/                     panels, dialogs, DiffView, LogList, GraphCell, …
    stores/                         Pinia stores, one per area
    composables/  menus/  lib/
  e2e/                              Playwright
build/                              Wails Taskfiles and packaging assets per platform
tools/
  gencore/                          go generate: RPC client, dispatcher, facade (TR-28)
  trace/                            requirement traceability check (TR-30)
  repocheck/                        tests for repository conventions (TR-23 to TR-25)
  licensecheck/                     licence check and THIRD-PARTY-NOTICES.txt
  mkrepo/                           generates test and benchmark repos
  bench/                            performance benchmark against the generated repo
.github/workflows/                  ci.yml, release.yml, bench.yml (nightly benchmark and e2e)
Taskfile.yml                        setup, test, lint, build, dev, ci
flake.nix, flake.lock, .envrc       Nix dev shell (TR-24)
LICENSE  README.md  CONTRIBUTING.md  CHANGELOG.md  CLAUDE.md
```

`.bench/` holds the generated 100k-commit benchmark repo. It is gitignored and rebuilt only when the generator's configuration changes.
